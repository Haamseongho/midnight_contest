# 실제 사람 검증·낭독 체크시트

**미실시 템플릿.** 3명은 프로젝트 내부의 소규모 이해도 점검 제안이며 공식 참가·제출 요건이 아니다. 사람 결과를 AI 모의답변으로 대체하지 않는다. 불필요한 이름/녹음/개인정보 대신 P1–P3 코드만 사용한다.

## 진행자 순서
1. 최종 공개 URL·배포SHA·브라우저·날짜/시각을 기록한다.
2. 처음 보는 사람에게 30초 동안 첫 화면, 이어 확인자 화면을 보게 한다. 먼저 정답을 알려주지 않는다.
3. 공개 조회/Recorded/회로 시연 구분을 질문한다. 답변은 그대로 요약한다.
4. 오해가 있으면 문구·위치를 수정한다. 재설명 후 정답과 최초 이해를 구분해 기록한다.

| 질문 | 정답에 포함돼야 할 경계 |
|---|---|
| Q1 무엇이 private인가? | secret 원문은 ledger field 아님. wallet/prover 처리는 별도 |
| Q2 무엇이 public인가? | commitment, claimed, contract/tx 및 연결가능한 metadata |
| Q3 누가 secret을 입력하는가? | holder 자기 환경; reviewer에게 전달하지 않음 |
| Q4 reviewer에게 wallet이 필요한가? | 전용 공개 조회에는 불필요 |
| Q5 USED면 지금 사람을 입장시켜도 되나? | 아니오, 과거 소비와 현재 사람 인증은 다름 |
| Q6 live / recorded / local circuit은? | 현재 indexer관찰 / 역사 거래 / 브라우저 회로 실행 |

| 사람 | 버전·날짜·시각 | Q1–Q6 실제 답 | 오해 | 수정·재검사 | 결과 |
|---|---|---|---|---|---|
| P1 | 미실시 | — | — | — | NOT_VERIFIED |
| P2 | 미실시 | — | — | — | NOT_VERIFIED |
| P3 | 미실시 | — | — | — | NOT_VERIFIED |

‘3명 모두 핵심 경계를 설명’은 내부 통과 제안이다. 실패나 생략을 숨기지 말고 제출팀이 기록을 보고 위험을 판단한다. 공식 마감과 필수 등록을 사람 모집 때문에 놓치지 않는다.
