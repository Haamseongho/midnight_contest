# Silent Pass — 사례 기반 추가 아이디어 제안

2026-09-26 · 상태: **사용자 A–F 전체 채택 / 구현·검수 진행**. 현재 결과는 [진행표](./ENHANCEMENT_PROGRESS.md)를 기준으로 한다. 아래는 제안 당시의 설계 의도를 보존한다.

U1–U4에서 이미 반영한 내용은 [기존 체크리스트](./BENCHMARK_CHECKLIST.md), 구현·배포 증거는 [검수 기록](./IMPLEMENTATION_EVIDENCE.md)에 있다. 이 문서는 그 다음 선택지를 제안하며 채택·개발 완료를 뜻하지 않는다. 표의 6개 묶음을 모두 다루고 국내 5개 팀은 개별 아이디어로도 구분했다.

## 출처 확인과 해석

- 국내 5개 팀은 같은 2025 블록체인&AI 해커톤 수상작이 맞다. 공동 주관사 [라온시큐어 공식 발표(2025-09-25)](https://www.raon.com/ko/about/news_list/view/453): 위임(We-im) 대상, zkBlock 최우수상, 성희청과·TodayRPG·Typha 우수상. 이전 자료에서 결선 진출만 확인했던 한계를 해소했다.
- 국내 사례의 업무 설명에서 설계 원칙을 가져온다. 해당 팀의 코드 품질·성능·보안성을 직접 검증한 것은 아니다. 아래 아이디어는 Silent Pass에 맞춘 제안이지 원작의 세부 기능을 그대로 확인했다는 주장이 아니다.
- [VaxZK](https://github.com/bochaco/vaxzk)는 발급기관·증명 요청·소지자·결과를 구분한다. [AnchorZK](https://github.com/0xstrong/AnchorZK#verification-portal)는 공개 확인 포털을 지갑·쓰기 경로와 분리한다.
- [EDDA 공식 수상 소개](https://midnight.network/blog/virtual-hackathon-winners)는 Q&A 서비스의 기능 데모와 발표 완성도를, [Brick Towers 공식 소개](https://midnight.network/blog/developers-navigate-public-and-private-states-in-the-midnight-sea-battle-challenge)는 실제 플레이 가능한 Sea Battle을 설명한다. EDDA Q&A와 별도 Sea Battle 참가팀 Edda Labs의 사례를 혼동하지 않는다.
- [Lens & Frens](https://ethglobal.com/showcase/lens-and-frens-ogedp), [Zhat’s Me](https://ethglobal.com/showcase/zhats-me-vioyt), [Selkie](https://github.com/DpacJones/selkie-usdm-escrow)는 각각 ZK 티켓팅, 신원/이메일 티켓 증명, 비밀 지식 기반 자산 claim이라는 인접 분야다. 국내 5개 팀과 같은 대회 수상작이라는 뜻은 아니다.

## 추천 선택

우선 **B(사용 장면과 상태 설명) + D(확인자 전용 화면) + E(심사자 가이드)**를 한 묶음으로 검토할 것을 권한다. 이미 검증된 작은 기능을 처음 보는 사람도 직접 이해하고 확인하게 만드는 데 집중한다. 이후 C(근거 패널), A(역할 흐름·관찰 요약), F(비교 자료)를 선택할 수 있다. F는 문서 중심의 독립적인 저부담 선택지다.

## 별도 설계가 필요한 기능 — 이번 제안과 분리

- 발급자 서명·등록기관 인증: 누구를 신뢰하는지, 키 등록/폐기/탈취를 어떻게 다룰지부터 결정. UI 이름·로고만으로 대체할 수 없다.
- 현장 입장·양도/암표 방지: 현재 요청·소지자·세션의 암호학적 결합과 replay 모델이 필요하다. QR/nonce를 화면에 추가하는 것만으로 해결되지 않는다.
- 만료·철회·여러 초대 관리: 계약 상태/회로/ABI/key 변경 가능성이 있어 새 localnet·Preview 검증 계획이 필요하다.
- 자산 에스크로·결제: 현재 제품과 다른 위험·권한 범위다. Selkie의 기능을 그대로 추가하지 않는다.
