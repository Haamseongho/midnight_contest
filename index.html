초대 코드를 공개하지 않으면서 사용 기록을 확인해야 할 때, 소지자는 자기 환경에서 비밀값을 증명하고 확인자는 지정된 계약의 공개 소비 기록을 읽습니다. 현재 방문자의 신원이나 입장 허가는 별도 판단입니다.

예를 들어, 소규모 비공개 모임에서 초대 코드를 보여 주지 않고 그 코드의 소비 기록만 확인합니다. 이 기록만으로 참석이나 본인을 확인하지는 않습니다.

초대의 소비 기록만 확인하고 싶을 때

주최자는 계약과 전달 경로를 정하고, 소지자는 비밀값을 보관합니다. 비밀값을 얻은 누구나 사용할 수 있으므로 발급자의 신뢰성과 전달 경로가 필요합니다. 확인자는 앱 배포자가 고정한 공개 계약만 조회합니다. 이는 발급자 인증이 아닙니다.

서비스 범위: Silent Pass는 송금·결제·에스크로 앱이 아닙니다. 지갑은 Midnight 계약의 배포와 사용 승인을 서명하고 네트워크 수수료를 지불하는 데만 사용되며, 이 계약은 사용자 자금을 보관하거나 다른 지갑으로 전송하지 않습니다.

  1. 01 주최자 · 발급

    무작위 비밀값을 만들고 커밋먼트만 Midnight 계약에 배포합니다.

  2. 02 참가자 · 보관

    비밀 채널로 값을 받아 자기 환경에서 1회 claim을 만듭니다.

  3. 03 확인자 · 공개 기록 조회

    지갑과 비밀값 없이 지정된 계약의 사용 기록을 읽습니다.

실제 회로의 실패와 성공 확인

매번 독립된 임시 세션에서 컴파일된 Compact 회로를 실행합니다. 아래 소지자의 패스와 네트워크 계약에는 영향을 주지 않습니다. 이 시연은 체인 거래나 ZK 증명 생성이 아닙니다.

    아직 회로를 실행하지 않았습니다.

    30초 / 3분 발표 리허설

    30초: 문제 → 현재 공개 조회 → 회로 오답/성공/재사용 거절 → 한계.

    3분: 문제·역할(30초) → 맥락·조회(40초) → 회로 시연(40초) → 과거 증거(30초) → UNKNOWN 복구(25초) → 한계(15초).

    계측은 발표자의 실제 낭독을 대신 검증하지 않습니다. 음성·개인정보를 수집하지 않습니다.

    거래 상태와 복구

    거래 작업 없음

    시간 초과는 취소가 아닙니다. UNKNOWN 동안 새 거래는 잠깁니다. 재연결 후 원래 거래 ID의 최종 결과를 확인하세요. 미사용 상태를 한 번 읽은 것만으로 실패를 확정하지 않습니다.

    전송 전 중단은 이후 앱의 전송을 막습니다. 남아 있는 Lace 승인창은 직접 거절하세요. 이미 전송한 거래는 취소할 수 없으며 결과 미확인 동안 보호를 유지합니다. 복구 정보는 이 탭의 세션에만 저장됩니다.

    지갑 연결이나 거래가 멈췄을 때

    같은 거래를 바로 다시 보내지 마세요. 먼저 Lace의 Activity, Preview 동기화, tDUST 잔액을 확인하세요. 공개 상태나 거래 식별자가 없다면 Lace를 다시 연 뒤 이 화면의 지갑 다시 연결을 사용하세요. 공개 상태의 미사용·미검출만으로 이전 거래 실패를 확정하지 마세요. 원래 거래 ID의 최종 결과를 확인하기 전에는 재전송하지 마세요. 배포와 사용 전에 앱이 tDUST 잔액을 확인하며, 잔액이 0이면 증명이나 거래 제출을 시작하지 않습니다.

    주의: 사용 시 비밀값은 로컬 Docker 증명 서버 또는 선택한 지갑의 증명 제공자에 전달될 수 있습니다. 이 앱 자체는 별도 저장하지 않지만, 해당 증명 서비스의 처리 방식은 별도로 확인해야 합니다.

    SMALL SCOPE · CLEAR EVIDENCE

    무엇이 다르고, 어디까지 하나요?

    제공함 지정 계약의 비밀 지식·일회 소비 회로, 지갑 없는 공개 소비 조회, 근거와 불확실성 표시.

    제공하지 않음 티켓 판매·본인 인증·온체인 발급기관 인증·입장 승인·송금·에스크로.

    다른 ZK 서비스와 무엇이 다른가요?

    범위가 다른 작은 프로토타입입니다. 기존 ZK 티켓팅·신원/이메일 증명·자산 claim과 달리 지정 계약의 소비 기록을 함께 확인하는 경로에 집중합니다. 세계 최초나 타 서비스보다 안전하다고 주장하지 않습니다.

    공식 프로젝트 설명(확인일 2026-09-26): Lens & Frens · ZK 티켓팅 · Zhat’s Me · 신원/이메일 티켓 증명 · Selkie · 비밀 기반 자산 claim. 외부 프로젝트를 직접 실행·감사하지는 않았습니다.

    사용 기록이 있으면 입장시켜도 되나요?

    아닙니다. 누가 비밀값을 사용했는지, 지금 제시자가 누구인지, 발급기관이 진짜인지 이 회로는 자동으로 확인하지 않습니다. 주최자는 별도의 신뢰·입장 정책을 정해야 합니다.

    다운로드한 관찰 요약은 증명서인가요?

    아닙니다. 서명되지 않은 저장 당시 관찰입니다. 변조될 수 있으며 현재 상태는 새로 조회해야 합니다. 과거 거래 ID와 이번 조회는 별도 증거입니다.
